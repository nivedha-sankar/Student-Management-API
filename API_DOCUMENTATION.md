Student Management API Documentation
1. Overview
This REST API manages student records using Node.js, Express.js, and PostgreSQL.
Base URL (local example): http://localhost:5000
Route prefix: /api/students
Replace port 5000 with the port configured in your server.js.
Content type: application/json
2. Student data model
A student record has the following fields:
Field      Type      Required                Description
id       integer   Generated by database   Unique student ID name     string    Yes                     Student name age      integer   Yes                     Positive whole-number age course   string    Yes                     Course name email    string    Yes                     Student email address
Example:
{
  "id": 7,
  "name": "Nive",
  "age": 20,
  "course": "Computer Science",
  "email": "nive48@gmail.com"
}
3. Endpoints
3.1 Get all students
Method: GET
Path: /api/students
Purpose: Returns all student records ordered by ascending ID.
Request body: None
Example request:
curl http://localhost:5000/api/students
Success response --- 200 OK:
{
  "success": true,
  "count": 1,
  "students": [
    {
      "id": 7,
      "name": "Nive",
      "age": 20,
      "course": "Computer Science",
      "email": "nive48@gmail.com"
    }
  ]
}
When the table is empty, count is 0 and students is an empty array.
3.2 Get a student by ID
Method: GET
Path: /api/students/:id
Purpose: Returns the student with the supplied ID.
Request body: None
Example request:
curl http://localhost:5000/api/students/7
Success response --- 200 OK:
{
  "success": true,
  "student": {
    "id": 7,
    "name": "Nive",
    "age": 20,
    "course": "Computer Science",
    "email": "nive48@gmail.com"
  }
}
Possible errors:
400 Bad Request --- ID is not a positive integer.
404 Not Found --- No student exists with that ID.
500 Internal Server Error --- Database or server error.
3.3 Add a student
Method: POST
Path: /api/students
Purpose: Creates a student record.
Header: Content-Type: application/json
Request body:
{
  "name": "Nive",
  "age": 20,
  "course": "Computer Science",
  "email": "nive48@gmail.com"
}
Example request:
curl -X POST http://localhost:5000/api/students \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"Nive\",\"age\":20,\"course\":\"Computer Science\",\"email\":\"nive48@gmail.com\"}"
Success response --- 201 Created:
{
  "success": true,
  "message": "Student added successfully",
  "student": {
    "id": 7,
    "name": "Nive",
    "age": 20,
    "course": "Computer Science",
    "email": "nive48@gmail.com"
  }
}
Possible errors:
400 Bad Request --- Required field is missing, age is not a positive whole number, or email format is invalid.
500 Internal Server Error --- Database or server error.
3.4 Update a student
Method: PUT
Path: /api/students/:id
Purpose: Replaces the supplied student's name, age, course, and email.
Header: Content-Type: application/json
Request body (all four fields are required):
{
  "name": "Nive Sharma",
  "age": 21,
  "course": "Full Stack Development",
  "email": "nive@example.com"
}
Example request:
curl -X PUT http://localhost:5000/api/students/7 \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"Nive Sharma\",\"age\":21,\"course\":\"Full Stack Development\",\"email\":\"nive@example.com\"}"
Success response --- 200 OK:
{
  "success": true,
  "message": "Student updated successfully",
  "student": {
    "id": 7,
    "name": "Nive Sharma",
    "age": 21,
    "course": "Full Stack Development",
    "email": "nive@example.com"
  }
}
Possible errors:
400 Bad Request --- Invalid ID or invalid/missing student details.
404 Not Found --- Student ID does not exist.
500 Internal Server Error --- Database or server error.
3.5 Delete a student
Method: DELETE
Path: /api/students/:id
Purpose: Deletes the student with the supplied ID.
Request body: None
Example request:
curl -X DELETE http://localhost:5000/api/students/7
Success response --- 200 OK:
{
  "success": true,
  "message": "Student deleted successfully"
}
Possible errors:
400 Bad Request --- ID is not a positive integer.
404 Not Found --- Student ID does not exist.
500 Internal Server Error --- Database or server error.
4. Validation rules
The API checks the following fields for POST and PUT requests:
name must not be empty.
age must be a positive whole number.
course must not be empty.
email must not be empty and must match a basic email pattern.
Example validation error --- 400 Bad Request:
{
  "success": false,
  "error": "Age must be a positive whole number"
}
Other validation messages include:
All fields are required
Please enter a valid email address
5. HTTP status codes
Status                        Meaning
200 OK                      Request succeeded 201 Created                 Student created successfully 400 Bad Request             Invalid ID or request data 404 Not Found               Student record does not exist 500 Internal Server Error   Unexpected server/database error
6. Error response format
Errors use JSON. For example:
{
  "success": false,
  "error": "Failed to fetch students"
}
A missing student may return:
{
  "success": false,
  "message": "Student not found"
}
7. Testing checklist
Test each operation against your running backend:
[ ]
GET /api/students --- list students
[ ]
GET /api/students/7 --- get one student (use an ID that exists)
[ ]
POST /api/students --- create a student
[ ]
PUT /api/students/7 --- update a student (use an ID that exists)
[ ]
DELETE /api/students/7 --- delete a test student (use a test ID)
[ ]
Try an invalid age and invalid email to confirm validation
[ ]
Try a non-existent ID to confirm the 404 response
Important: The sample IDs and student details above are examples. Use your own test records. Do not delete real student data while testing.
8. Notes
These documents describe the routes and response shapes in the provided routes/students.js code.
The backend port and environment variable names depend on the actual server.js and db.js configuration. Update the local base URL and setup instructions if your project uses different values.
The CSV download and name-search features shown in the React interface are frontend features; they are not listed as REST API endpoints unless separate backend routes have been implemented for them.
